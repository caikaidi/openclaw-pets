# OpenClaw Pets v0.5 interaction specification

## Todo

- The right-click panel has Activity, Todo, and Settings tabs.
- Todo is regenerated from the recent 30-day Journal and is not independently
  stored.
- Entering Todo re-reads the Journal but reuses the process-local summary when
  the bounded Journal snapshot is unchanged. New, edited, or retracted
  observations invalidate it. The explicit re-summarize action bypasses this
  cache. Clients that do not send the optional cache preference retain the
  earlier force-regeneration behavior.
- The summarizer receives Journal observations plus current-time and time-zone
  control metadata, but no tools, execution runtime, Session history, Memory,
  or other outside context.
- Every accepted Todo cites one or more exact Journal observation ids; output
  with unknown citations or malformed fields fails closed.
- Completed, cancelled, superseded, and duplicate work is omitted or merged.
- Provider gaps remain visible and never become a false empty state.

## Apple actions

- Each Todo has separate one-click actions for Apple Calendar and Reminders.
- An explicit Journal due time is preserved.
- An unscheduled Todo shows the next work-slot Calendar time before export;
  Reminders keeps it without a due date.
- Only the clicked Todo is sent to the selected Apple application. Fixed
  scripts and structured arguments prevent Journal text from becoming code.
- macOS consent denial is reported with the Automation settings path.
- Non-permission AppleScript failures are reported separately instead of being
  misdiagnosed as missing Automation consent.

## Menu recording and status

- The pet remains clickable while the panel is open.
- Listening, transcribing, terminal, and transient states render in the gap
  between panel and pet without moving either surface.
- A task-candidate route closes the panel so the existing confirmation card
  cannot be hidden behind it.

## Pointer geometry

- Raster Pet Packs test pointer coordinates against alpha in the currently
  rendered spritesheet frame.
- Transparent pixels keep the normal cursor and cannot click, drag, or open
  the context panel.
- Opaque pixels use grab/grabbing cursors. The built-in code-native pet uses a
  bounded polygon matching its visible body instead of the full viewport.
