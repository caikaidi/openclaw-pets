# OpenClaw Pets v0.5 interaction specification

## Todo

- The right-click panel has Activity, Todo, and Settings tabs.
- Todo is regenerated from the recent 30-day Journal and is not independently
  stored.
- Entering Todo re-reads the Journal but reuses the process-local summary when
  the bounded Journal snapshot is unchanged. New, edited, or retracted
  observations invalidate it. The explicit re-summarize action bypasses this
  cache. Clients that do not send the optional cache preference retain the
  earlier force-regeneration behavior.
- The summarizer receives Journal observations plus current-time and time-zone
  control metadata, but no tools, execution runtime, Session history, Memory,
  or other outside context.
- Every accepted Todo cites one or more exact Journal observation ids; output
  with unknown citations or malformed fields fails closed.
- Completed, cancelled, superseded, and duplicate work is omitted or merged.
- Provider gaps remain visible and never become a false empty state.

## Editing

- Todo title and notes have an explicit local editor; the revised item feeds
  both display and Apple export. Revisions are stored on this Mac using the
  existing native secure_get/secure_set vault, not in the Journal or a new API.
  Saving awaits successful persistence; failure retains the draft and previous
  value. Refresh and a new App instance restore the same revision.
- The vault record is versioned, isolated by Gateway URL, and bounded to 100
  entries / 60000 UTF-8 bytes (below the native 65536-byte value limit). Corrupt
  data, unsupported versions, capacity or storage errors are visible failures;
  they never silently overwrite the cache or report a successful save.
- Identity uses sorted exact source observation IDs plus original title, notes
  and due time. It does not trust the generated Todo ordinal or JSON key order.
  Changed source association/content invalidates a revision. A complete summary
  removes absent revisions; a partial/unavailable response is not deletion.
  Successful explicit re-summarize resets revisions durably. Failed requests
  leave them intact. The protocol exposes source IDs, not Journal revisions:
  edits to a Journal observation that regenerate identical Todo content cannot
  be distinguished here; no claim of raw-Journal revision tracking is made.
- Editing an exported Todo does not update the existing Apple item. Existing
  export markers are retained on local save, refresh, reload and re-summarize.
  Export receipts use the same source identity and are not automatically evicted;
  capacity exhaustion fails visibly. Persistence never invokes Apple export.
  Apple success followed by a receipt-write failure remains a cross-system
  partial failure; it is not an exactly-once transaction across macOS and the
  local vault. The in-memory marker remains set; check Apple before retrying.
- Todo and Journal text areas use Enter to save and Shift+Enter for a newline.
  Composition, keyCode 229, and compositionend-before-keydown Enter are guarded;
  an unidentified end-before-keydown confirmation has an 80ms safety interval,
  not an indefinite pending latch. Observed Space/digit selection is distinct
  from Enter; Enter keyup ends the guard. Mouse/native candidate selection may
  provide no distinguishing DOM key, so an Enter inside that 80ms interval is
  conservatively guarded. An independent Enter after the interval saves on its
  first press. Arbitrarily delayed inverted events are not assumed to be IME
  confirmation. Synthetic event-order tests are not real WebKit/native IME tests.
- Held Enter cannot repeat saves. Journal keeps its in-flight guard, revision
  checks, conflict handling and failure draft. Todo validation stays in the
  editor with an error. Keyboard help is shown next to the edit controls.

## Visual focus

- Losing focus pauses the pet at its current displayed frame, without adding
  dimming or desaturation. Native and DOM events are observed, with an initial
  native focus query and cleanup including late-resolving subscriptions.
- Native menu layout hide/show events are ignored during transition; actual
  focus is reconciled afterwards. Regain resumes elapsed animation time rather
  than advancing through the unfocused interval. State changes received while
  paused are applied to pet artwork on regain; status/capture UI stays live.
- The built-in pet pauses its descendant CSS animations. Sprite Pet Packs pause
  their RAF timeline. A 650ms alpha-shaped drop-shadow pulse on the pet visual
  layer acknowledges regain; no window-level glow or extra status label is added.
- Recording, transcription, Todo requests and status timers do not use the
  visual focus timeline. The original 96% press feedback is unchanged.
- First-click activation policy is unchanged. The current source does not set
  acceptFirstMouse; the macOS native default remains false. This is a source
  finding, not a native first-click interaction test.

## Apple actions

- Each Todo has separate one-click actions for Apple Calendar and Reminders.
- An explicit Journal due time is preserved.
- An unscheduled Todo shows the next work-slot Calendar time before export;
  Reminders keeps it without a due date.
- Only the clicked Todo is sent to the selected Apple application. Fixed
  scripts and structured arguments prevent Journal text from becoming code.
- macOS consent denial is reported with the Automation settings path.
- Non-permission AppleScript failures are reported separately instead of being
  misdiagnosed as missing Automation consent.

## Menu recording and status

- A click outside the panel dismisses it; the close button remains available.
  A pet click used to dismiss the panel is consumed rather than also toggling
  recording. A subsequent pet click retains its recording action.
- Transparent-window presses and external focus loss dismiss the panel without
  stopping capture. Programmatic hide/show during a layout transition does not
  count as external focus loss.
- All tabs expose recorder-owned status and elapsed time, plus stop, cancel-start
  or recovery as applicable. Stopping remains pending until resource release is
  confirmed. Transcription explicitly indicates that the microphone is released.
- Listening, transcribing, terminal, and transient states render in the gap
  between panel and pet without moving either surface.
- The existing capture status pill stays 34 logical pixels above the pet's top
  both with and without the panel; no side label is added. Other non-capture
  status bubbles retain their normal layout when the panel is closed.
- A task-candidate route closes the panel so the existing confirmation card
  cannot be hidden behind it.

## Pointer geometry

- Raster Pet Packs test pointer coordinates against alpha in the currently
  rendered spritesheet frame.
- Transparent pixels keep the normal cursor and cannot click, drag, or open
  the context panel.
- Opaque pixels use grab/grabbing cursors. The built-in code-native pet uses a
  bounded polygon matching its visible body instead of the full viewport.
- Pressing scales only the pet's visual layer to 96%, about its center, with a
  180ms smooth restoration. Pointer release, cancellation, leaving the hit shape,
  lost capture, blur and drag restore it; a move reporting no pressed button
  also clears a missed release. The panel, status label and alpha/polygon hit
  geometry do not scale. Reduced-motion preference disables the transition.
